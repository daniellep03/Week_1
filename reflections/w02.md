This week, one term that stood out to me was API rate limiting. Rate limiting is when an API only allows a certain number of requests in a short amount of time. It helps keep the server from getting overloaded and makes sure everyone can still use the service fairly.
I applied this idea while working on the Job Pack project and learning about the class LLM endpoint. Since the endpoint is shared by the class, I realized that sending too many requests over and over could slow things down or cause errors. Because of that, I tried to be more careful when testing my prompts instead of constantly refreshing or retrying requests while debugging.
I also learned how frontend applications connect to backend AI systems through APIs. Before this week, I mostly thought about the design side of websites, but now I understand more about what happens behind the scenes when a user sends a request to an AI model. It helped me understand that websites are not only about appearance, but also about how data is sent and received between systems.
Another thing I thought was interesting was streaming responses. Instead of waiting for the whole response at once, the text can appear little by little, which makes the app feel faster and smoother for users. I think this improves the user experience because it feels more interactive and responsive.
Overall, this week helped me understand how APIs work in real projects and why it’s important to use them efficiently when building AI applications. It also gave me a better understanding of how frontend and backend systems work together in modern web development, especially when handling shared resources and real-time data flow in applications. It also helped me think more carefully about performance and responsible API usage in development.
